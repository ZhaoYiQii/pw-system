# 商家端 UI 设计框架 v1（UI 先行 · 后端后接）

- 状态：草案待评审（用户已确认方向，尚未进入切片实现）
- 日期：2026-09-08
- 范围：`apps/admin-web/app/(tenant)` 商家端
- 原则：先固定 UI 框架与信息架构；具体业务后端与真实权限接口后续补全，UI 用可替换的 mock 权限数据先行运行

## 1. 目标与非目标

目标：

1. 一套商家端代码、一套视觉语言，服务店老板/店长/客服/财务四个角色。
2. 店老板端持有全量模块；其他角色按权限只看到被授权的模块与动作。
3. 页面结构统一为三台：工作台、记录台、监控台，另设门店设置。
4. UI 优先于后端：前端先以本地 mock 权限驱动，后端接口就绪后只替换数据来源，不重做 UI。

非目标：

- 本框架不实现真实鉴权；权限以"前端展示 + mock 数据"为契约，安全边界在后端补全时强制执行。
- 本框架不包含平台端（`(platform)`）、陪玩 H5、老板 H5、微信小程序 UI。
- 本框架不引入任何真实业务接口、支付、短信或 AI Provider。

## 2. 视觉基线（来自已确认原型）

视觉语言以 `design-demos/merchant-console-three-desks.html`（pw-ui-v3 的三台改造版）为基座，并保留仓库既有约束（Tailwind v4 + shadcn/ui + TanStack Query）。

### 2.2 字体与数字

- 界面主字体：`"Microsoft YaHei UI" / "PingFang SC" / "Noto Sans CJK SC"` 系统栈。
- 编号、金额、时长、时间：`--mono` 等宽数字栈（Cascadia Mono / SFMono / Consolas）+ `font-variant-numeric: tabular-nums`。
- 字号基调：导航与正文 12–13px；标题 27px；等宽数字为信息主角时可用 23px 大字。

### 2.3 组件质感

- 轻边框 + 暖纸面；主操作陶土橙，成功态鼠尾草绿。
- 列表负责判断，详情负责完成动作。
- 一页只有一个主要动作；状态文字与下一步动作一一对应。
- 所有金额、时长、状态以服务端结果为准（UI 阶段用演示数据并标注）。

### 3.1 角色

### 3.2 UI 权限契约（前端先行）

UI 只消费一个权限描述对象，不在前端写死每个角色能看什么：

```ts
type RoleCode = 'OWNER' | 'ADMIN' | 'CS' | 'FINANCE';

type UiPermission = {
  role: RoleCode;
  nav: Array<{ group: string; id: string; label: string }>;
  actions: string[]; // 例如 'order.confirm' 'settlement.approve'
};
```

- 导航与操作按钮只根据 `nav` / `actions` 渲染。
- UI 阶段使用 `src/__mock__/permissions.ts` 按角色返回该对象；后端就绪后由 `/me/permissions`（或等价接口）替换。
- 前端隐藏不等于授权：真实权限必须由后端执行；直连无权限路由时显示 403 页面。
- 若未来需要"店老板给单个员工额外勾模块"，将新增独立权限模型（涉及后端/数据层），不在本框架内伪装。

## 6. 统一页面模板

所有模块复用以下模板：

1. **工作台模板**：今日脉搏 + 待办队列 + 右侧节奏/提醒。
2. **列表模板**：PageHeader + FilterBar + Tabs + DataTable + 分页/导出。
3. **详情模板**：主内容（事实区 + 状态/席位/时间线）+ 右侧固定操作栏。
4. **档案模板**：资料卡 + 关系时间线（历史订单/场次/结算）。
5. **监控模板**：指标/风险流 + 实时行列表 + "去处理"深链。
6. **表单/向导模板**：新建订单、门店配置等长流程。
7. **403/空/错误模板**：权限不足、空结果、加载失败、断网重试。

## 8. 跨页面行为规范

- 五种状态必做：loading / empty / error / offline-retry / permission-denied。
- 金额与时长全部使用等宽数字、语义色、服务端为准；UI 演示数据须标注"演示"。
- 按钮文案使用明确动词与结果一致："确认需求"后出现"已确认需求"；禁止含糊的"提交"。
- 关键写操作先确认弹窗；涉及状态迁移/金额/人选的操作同时展示将产生的结果。
- 表格密集但可扫描：行高适中、状态徽章一致、每行提供唯一主操作。
- 移动与窄屏：侧栏折叠、表格横滑、详情操作栏回到页面内；键盘焦点与 reduced-motion 完整支持。

## 10. 验收标准

- 导航由 `UiPermission` mock 驱动：切换角色后导航与按钮即时变化，且不存在"隐藏了但直连可达白屏"。
- 三台导航中所有条目有页面或统一模板占位，无空链接。
- 金额、时长、状态、席位、报名与确认动作的演示交互闭环。
- 打开浏览器点击后无控制台错误、无横向溢出；键盘可完成主要操作。
