# 派单模板表单设计器 设计规格 v0.2（原语优先）
- 状态：**已获用户批准**（2026-09-18「目前看着不错，继续完善然后直接开始开发」）
- 日期：2026-09-18
- 与 v0.1 的关系：本版**只修订「内容设计」Tab 的编辑体验**；v0.1 的数据模型、接口契约、迁移与快照部分继续有效，不因本版失效。
- 范围：`apps/admin-web/app/_lib/merchant-console/**` 的模板编辑器视图层。
- 非目标：不改后端服务、不改 OpenAPI 契约、不新增迁移、不改下单渲染与订单快照、不引入拖拽画布。

## 1. 背景
v0.1 的实现把后端数据模型直接铺在界面上：每个字段要填「业务用途」（10 项枚举）、界面常显 `fieldKey: xxx`、选项区印着开发待办、区块要设列数与跨列，顶部还有「参考预设」入口。门店店长看不懂，而且预设目录替用户决定了「表单里有什么」。

用户裁定（2026-09-18）：**不需要给用户定预设，只需要给足够的自由度让他们自己自定义表单。**

## 2. 决策
| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D-13 | 只给原语，不给预设 | 删除任何「常用字段目录」「岗位与人数」「选择项加价」类预设入口；不替用户决定表单里有什么 |
| D-14 | 四种新建动作 | 新建字段 / 新建表格 / 新建说明 / 新建分组；点下去一律是空白项 |
| D-15 | 行 + 展开属性面板 | 行默认只显示「编号 · 类型 · 名称 · 属性摘要 · 状态标签」；选中后在行下方展开完整属性面板，密度落在面板里 |
| D-16 | 保留编号轴与联动 | 左栏第 n 项与右侧预览第 n 个字段共用编号；悬停/聚焦任一侧，两侧同时点亮 |
| D-17 | 预览复用真实渲染器 | 预览交给 `TemplateDraftRenderer`，禁止另写一套预览渲染，避免预览与下单页漂移 |
| D-18 | 校验徽标复用既有问题模型 | 行尾问题数来自 `collectDraftIssues`，不新造校验逻辑 |
| D-19 | 算价绑定保留为可选 | 「用于算价」= 不用 / 人数 / 时长；不绑也能保存与发布，金额由客服手填；已被占用的取值不可再选 |

## 4. 数据流
1. 加载：`fetchTemplateDraft` → `toDraftConfig` → `DraftConfigV2`（既有）。
2. 编辑：所有修改走 `template-draft-state.ts` 既有操作函数（`addComponent` / `updateComponent` / `moveComponent` / `removeComponent` / `toggleComponentEnabled` / `addSection` / `updateSection` / `moveSection` / `removeSection` / `addTableColumn` / `removeTableColumn` / `updateTableColumn` / `setComponentOptions` / `addDefaultRow` / `removeDefaultRow`），视图只调用与呈现。
3. 预览：草稿 → 既有渲染器输入结构 → `TemplateDraftRenderer` 只读渲染。
4. 保存 / 发布：沿用既有 `saveTemplateDraft` 与发布流程，本版不改。

## 5. 失败处理
| 场景 | 处理 |
| --- | --- |
| 操作返回 `{ ok: false }` | 不改变草稿，用 `onNotice` 给出原因（沿用既有 result 模型） |
| 删除仍被岗位来源引用的组件 | `guardRemoveComponent` 拦截并提示（既有） |
| 删除仍被引用的表格列 | `guardRemoveTableColumn` 拦截并提示（既有） |
| 取消选中 | 面板收起，不丢数据 |
| 字段名为空 | 允许保存；行内显示占位名与问题徽标，不阻塞 |

## 6. 边界与安全
- 前端只决定呈现，不构成安全边界；权限 `gameDispatch.manage`、租户绑定、金额口径全部不变。
- 不新增字段标识（`stableKey`）的手工编辑入口，标识仍由系统生成。
- 不引入新的全局状态库；沿用现有组件内 state + TanStack Query。

## 7. 测试与验收
- 模型层：`template-draft-state.spec.ts` 既有用例继续全绿（本版不改模型）。
- 视图层新增纯函数单测：类型标签、属性摘要、行问题数、算价取值占用判定。
- 无障碍：复用 `template-a11y` 的焦点策略，键盘可达，`aria-expanded` / `aria-pressed` 正确。
- 门禁：`corepack pnpm --filter @pw/admin-web typecheck`、`--filter @pw/admin-web build`、admin 单元套件。

## 8. 回滚
纯前端视图层改动；回滚 = 恢复 `template-editor-content.tsx` 与新增文件。无数据迁移、无契约变化、无持久副作用。

## 9. 本版明确不做
1. 业务绑定与计算 Tab 的重做（沿用现状）。
2. 发布设置与版本历史的重做（沿用现状）。
3. 预设机制的**函数级删除**（`insertPreset` / `DraftPreset`）——本版只解除界面调用，函数删除作为独立清理任务。

## 10. 追加决策（2026-09-18 视觉对齐）

背景：首版实现落在了仓库里，但只做了结构与行为，没有把本规格批准时的视觉语言做进去——控件被塞进边框盒子、预览渲染成了配置诊断视图、编号轴缺失。以下两条是补齐。

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D-20 | 右栏预览是**客户视角呈现**，不是配置诊断视图 | 预览只显示客户会看到的东西：标签（必填带 `*`）、输入框样式、选项胶囊（含每项加价）、表格表头与行、说明块、分组标题。`整行/半行`、`N 列`、字段类型枚举等诊断信息只允许出现在属性面板。**修订 D-17 的落地方式**：布局仍复用同一套装箱规则 `layoutV2Rows`，但预览由 `TemplateDraftRenderer` 呈现，而不是复用诊断式渲染。 |
| D-21 | 编辑器只使用商家端既有视觉层 | 行保持安静（默认无边框，悬停或激活才有底色与编号高亮）；编号轴用一条竖细线加编号方块表达；分组是轻分隔标题而非卡片；属性面板用浅底面板承载密度。颜色与圆角一律取 `--mc-*` token，不引入新颜色。 |
| D-22 | 客户视角从并排面板改为「渲染」弹层 | 编辑器改为单列清单；工具栏右侧「渲染」按钮打开弹层，在弹层里看客户视角（`填写表单` / `订单文案` / `手机宽度` 三个切换，Esc 或点遮罩关闭）。**这取代了 D-16 的「并排联动」**：编号仍保留在清单里，但两侧同时高亮的联动不再适用——同一时刻只能看到一侧。弹层用 `createPortal` 挂到 `body`，并自带 `pw-merchant` 作用域以复用商家端 token。 |
| D-23 | 实现必须对齐原型的视觉参数 | 行的内边距 `8px 16px 8px 0`、编号方块 22×22、类型列 34px、名称 14px/500、元信息 12px、工具按钮 26×26、chip 高 28、属性面板左缩进 40px；颜色一律取 `--mc-*`，不再使用 Tailwind 默认灰阶与 amber 调色板。 |
| D-24 | 模板列表可隐藏 | 模板管理页页头提供「隐藏 / 显示模板列表」开关，隐藏后栅格降为单列、编辑区占满宽度。按钮必须在列表**之外**（放在列表内会导致隐藏后无法恢复），并带 `aria-pressed` 与 `aria-controls`。 |
