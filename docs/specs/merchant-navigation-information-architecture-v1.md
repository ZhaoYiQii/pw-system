# 商家端模块导航信息架构 v1

- 状态：v1 已在工作树实现（2026-09-10，未提交）：8 个业务域、18 个活动模块、15 个 preview、19 个 planned
- 验收证据：`apps/admin-web/app/_lib/merchant-console/modules.spec.ts`（6 用例）与 `tests/e2e/merchant-console-admin.spec.ts` 已同步；2026-09-11 定向单测全绿
- 实施计划：`docs/superpowers/plans/2026-09-10-merchant-module-navigation.md`

## 目标

把现有商家端真实模块与参考系统中有价值的能力统一收进简洁的两级导航。侧栏只承担一级业务域和二级功能页，三级能力放进页面标签、筛选器或详情动作。

## 导航结构

1. 经营台：经营总览、待办中心、进行中服务、消息中心、智能助手。
2. 订单履约：订单中心、新建订单、派单工作台、抢单大厅、场次与证据、评价管理、售后纠纷。
3. 客户陪玩：客户档案、陪玩档案、入驻审核、员工管理、排班管理、标签分组、关系管理。
4. 商品店铺：游戏品类、服务商品、价格方案、分成方案、附加服务、限购方案、技能证书、店铺装修、小程序管理。
5. 营销会员：优惠活动、邀请奖励、会员成长、权益礼包、用户背包、互动玩法。
6. 财务结算：经营入账、资金账单、支付退款、结算批次、提现管理、财务对账、欠款追踪。
7. 数据风控：综合分析、经营趋势、业绩排行、客户关怀、流失预警、私单风险、异常监测。
8. 运营设置：门店资料、员工权限、通知规则、套餐功能、渠道管理、审计日志、帮助中心。

## 三种模块状态

- `active`：页面和真实后端已接通；按角色正常显示并可导航。
- `preview`：UI 方向已纳入规划但业务未接通；只向店老板展示，点击后显示功能预览说明，不伪造业务数据或成功结果。
- `planned`：已登记的未来能力；不进入日常展开列表，只计入该业务域的“规划中”数量，并可在功能预览面板中查看名称和建设范围。

任何模块从 `preview` 或 `planned` 转为 `active` 时，必须同时满足后端权限、API、页面状态和测试，不允许只修改前端状态。

## 角色与套餐

导航继续使用现有 OWNER、ADMIN、CS、FINANCE 角色矩阵。前端状态只控制呈现，后端授权仍是安全边界。未来接入套餐能力时，菜单、路由、API 与异步任务必须受同一 entitlement 控制。

## 交互规则

- 桌面侧栏默认只展开当前页面所属业务域；用户可手动展开其他业务域。
- 二级活动页是链接；预览页是按钮并带“预览”状态；规划项不混入日常导航。
- 当前页、键盘焦点、展开状态和状态标识必须可辨识。
- 窄屏沿用现有抽屉式侧栏；选择活动页后关闭抽屉。
- `preview` 和 `planned` 不显示虚假金额、订单、成功提示或模拟业务结果。

## 首个实现 Slice

本次只完成导航模型、两级折叠交互、三种状态呈现和功能预览面板。复用现有路由，不新增 API、数据库、依赖或业务数据；不修改陪玩端底部导航。

## 验收

- 8 个一级业务域都可见，当前业务域自动展开。
- 现有 18 个模块保持原有角色可见性和路由能力。
- 店老板可识别 `active`、`preview`、`planned`；其他角色不看到未启用模块。
- 预览项不会发起业务请求；规划项不会制造可点击的假功能。
- 键盘、移动抽屉和现有跳转行为无回归。
