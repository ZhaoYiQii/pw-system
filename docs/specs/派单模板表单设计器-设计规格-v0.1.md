## 1. 背景与目标

现状（2026-09-12 代码核对）：

- 游戏模板已有字段模型，支持自定义命名、类型、必填/可选、选项、占位提示、排序：`GameDispatchTemplateField{fieldKey,label,fieldType,required,options,placeholder,sortOrder,enabled}`。
- 已有岗位档位 `GameDispatchPosition`、段位加价 `GameDispatchRankRule`、复制文案 `copyLines`。
- 已有接口 `/api/v1/tenant/game-templates`（增删改查 + 复制），权限 `gameDispatch.manage`。
- 已有编辑器：`/game-templates`（列表）与 `/game-templates/[id]`（编辑器）；新建派单页 `/merchant-console/dispatch/new` 已按模板动态渲染字段与岗位。

本次要解决的三件事：

1. 新建派单从"跳二级页"改为**弹窗表单**。
2. 左侧"订单中心"下增加**三级菜单 · 模板管理**。
3. 模板管理升级为**表单设计器**：自定义模块（分区）、行/列布局、字段命名、必填/可选。

目标：门店能针对不同游戏与需求，用可视化设计器做出自己的派单表单样式，并在新建派单弹窗里立刻看到效果。

## 2. 范围与非目标

范围内：

- 模板的"模块（分区）+ 行列布局"数据模型、接口与快照扩展。
- 三级导航（订单中心 → 派单工作台 / 模板管理）。
- 新建派单弹窗化（保留原路由兼容）。
- 模板管理页（列表 + 编辑器 + 实时预览）。

非目标（本次不做）：

- 不改订单/派单/场次/结算状态机，不改金额口径。
- 不引入拖拽式自由画布（本版是"模块 + 网格"结构化设计器，不做绝对定位画布）。
- 不做模板的跨门店共享/平台级模板市场。
- 不引入乐观锁并发控制（沿用现有覆盖式更新；门店内并发编辑概率低，列为已知限制）。
- 不改移动端 H5 的表单呈现（该表单只在 admin 商家端渲染）。

## 3. 已确认决策

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D-1 | 数据模型采用"结构化分区"（方案 A） | 新增 `game_dispatch_template_sections` 表；字段表增加分区与列宽；快照同步扩展。理由：字段定义已有单一权威源，布局必须与字段一起被快照固化 |
| D-2 | 模块呈现形态为**横向分区** | 分区标题一行 + 其下字段网格；不使用并排分组卡片 |
| D-3 | 列数上限 1–4 列，默认 1 列 | 窄屏（<768px）自动降为 1 列渲染 |
| D-4 | 老模板自动迁移为"默认模块 + 单列" | 迁移脚本回填，不改店主已有的字段命名与必填设置 |
| D-5 | 三级菜单只放"派单工作台 / 模板管理" | "新建派单"不做菜单项，保留为按钮 + 弹窗 |
| D-6 | 保留 `/merchant-console/dispatch/new` 路由 | 直接访问、AI 录单带入、E2E 深链继续可用；内部与弹窗复用同一表单组件 |
| D-7 | 行/列语义 = 分区列数 + 字段跨列 + 另起一行 | 不引入显式 rowIndex，避免重排后行号失配 |
| D-8 | 权限沿用 `gameDispatch.manage` | 与现有模板/派单接口一致，安全边界仍在后端 |

## 4. 数据模型设计

### 4.1 新表 `game_dispatch_template_sections`

| 列 | 类型 | 约束 |
| --- | --- | --- |
| id | uuid | PK, default uuid |
| tenant_id | uuid | 非空 |
| template_id | uuid | 非空 |
| name | text | 非空，1–30 字符 |
| columns | int | 非空，默认 1，取值 1–4 |
| sort_order | int | 非空 |
| enabled | bool | 非空，默认 true |
| created_at / updated_at | timestamptz | 非空 |
| version | int | 非空，默认 1 |

- 唯一索引：`(tenant_id, template_id, name)`
- 查询索引：`(tenant_id, template_id, sort_order)`
- RLS：与其他租户表一致，建 `tenant_isolation_runtime` 策略授予 `pw_runtime`

### 4.2 `game_dispatch_template_fields` 增列

| 新列 | 类型 | 约束 |
| --- | --- | --- |
| section_id | uuid | 可空；指向本模板的 section |
| col_span | int | 非空，默认 1，取值 1–4，且 ≤ 所属 section.columns |
| row_break_before | bool | 非空，默认 false；true 表示该字段另起一行 |

`sort_order` 语义不变：模板内全局顺序；同分区内按 `sort_order` 升序排列并装箱。

### 4.3 快照扩展 `game_dispatch_template_snapshots`

- 新增列 `sections_json`（Json，默认 `[]`），保存下单时的分区定义（name/columns/sortOrder）。
- `fields_json` 每条增加 `sectionId / colSpan / rowBreakBefore`。
- 历史快照兼容：无 `sections_json`、字段无 `sectionId` 时，渲染器按"单分区、单列"回落；`form_values_json` 仍是打平的 `key→value`，**不改历史数据**。

### 4.4 迁移与回填

- 迁移名：`20260912090000_dispatch_template_sections`（additive：建表 + 加列 + 回填）。
- 回填：为每个已有模板插入一条分区 `name='基本信息', columns=1, sort_order=0`，并把该模板全部字段的 `section_id` 指向它。
- 回滚：删列（`sections_json`、`section_id`、`col_span`、`row_break_before`）+ 删表；无破坏性数据变更。

## 5. API 契约变更

沿用 `/api/v1/tenant/game-templates`，在现有响应体上**新增字段**（不破坏既有调用方）：

```jsonc
{
  "id": "...",
  "name": "三角洲护航",
  "enabled": true,
  "sections": [
    { "id": "...", "name": "需求信息", "columns": 2, "sortOrder": 0, "enabled": true }
  ],
  "fields": [
    {
      "id": "...",
      "fieldKey": "server",
      "label": "区服",
      "fieldType": "text",
      "required": true,
      "options": [],
      "placeholder": null,
      "sortOrder": 0,
      "enabled": true,
      "sectionId": "...",
      "colSpan": 1,
      "rowBreakBefore": false
    }
  ],
  "positions": [],
  "rankRules": [],
  "copyLines": []
}
```

写入（POST/PATCH）：

- 接受 `sections[]`；未提供时：新建模板自动创建默认分区 `基本信息`（columns=1）；更新模板保持现有分区不变。
- 字段的 `sectionId` 可空；为空时归入该模板 `sortOrder` 最小的分区。
- 校验规则（服务端权威，返回 400 并说明原因）：
  - `columns` 与 `colSpan` 取值 1–4；
  - 同一分区内 `colSpan` 之和按装箱不超列数，若超列数则拒绝；
  - 分区 `name` 在同一模板内唯一且非空；
  - `fieldKey` 仍按现有规则（同模板唯一、允许字符集不变）。
- 契约变更走 `pnpm openapi:generate` 更新 `openapi.yaml`/`openapi.json`/`packages/api-client`，CI 由 `openapi:check` 把关。
- 校验规则按仓库既有模式登记在 `apps/api/src/common/validation/api-validation-rules.ts`。

## 6. 前端设计

### 6.1 三级导航

- `modules.ts`：把 `dispatch`（订单中心）由叶子项升级为可展开分组，`children = [派单工作台(/merchant-console/dispatch), 模板管理(/merchant-console/dispatch/templates)]`；角色可见性沿用现有矩阵，`ADMIN`/`CS` 是否可见模板管理与现有 `gameDispatch.manage` 授权保持一致。
- `merchant-shell.tsx`：一级业务域展开状态之外，新增二级分组展开状态；按钮带 `aria-expanded` / `aria-controls`。
- `merchant-console.css`：新增 `.mc-nav-group*` 样式，复用现有 token 与移动抽屉行为。
- 路由 `/merchant-console/dispatch/templates` 为静态段，优先级高于 `[module]` 动态段，不冲突。

### 6.2 新建派单弹窗

- 把 `new-order-view.tsx` 的表单主体抽成可复用组件 `NewOrderForm`（字段渲染 + 校验 + 提交），行为不变。
- 新增 `NewOrderDialog`（shadcn 风格 `Dialog`）包裹 `NewOrderForm`；打开时聚焦第一个字段，`Esc`/遮罩可关，提交成功后关闭并刷新列表。
- 入口替换：工作台"新建派单"、订单中心列表"新建派单"、AI 录单带入后的跳转 → 打开弹窗。
- `/merchant-console/dispatch/new` 保留：整页渲染 `NewOrderForm`；带 `?templateId=` 时预选模板。

### 6.3 模板管理页

布局：左侧模板列表（新建 / 复制 / 启停 / 删除），右侧编辑器。

编辑器能力：

- 模块卡片：新增、改名（≤30 字）、设置列数（1–4）、上移/下移、启用/停用、删除（二次确认，子字段一并删除）。
- 字段行：命名、类型（text/select/multiline/datetime/duration/note）、必填开关、选项（select 时按行输入）、占位提示、跨列数（1..该模块列数）、另起一行、上移/下移、删除。
- 实时预览：右侧"预览"按与弹窗完全相同的渲染器生成只读表单。
- 保存：整模板 PATCH；失败时保留本地编辑态并提示原因；未保存离开需确认。
- 缩小模块列数导致字段 `colSpan` 越界时，前端自动把该字段 `colSpan` 收敛到新列数并提示用户。

### 6.4 渲染器（纯函数）

新增 `layoutTemplateForm(sections, fields)`：过滤停用项 → 按分区分组 → 分区内按 `sortOrder` 排序 → 依据 `colSpan` 与 `rowBreakBefore` 装箱成 `rows[]` → 返回可直接渲染的结构。

响应式：容器宽度 < 768px 时按 1 列渲染（不改数据）。

## 7. 权限与租户边界

- 后端：所有模板读写继续要求 `gameDispatch.manage` 且绑定 `TenantContext.tenantId`；分区属于模板，必须校验 `section.templateId` 与 `section.tenantId`，禁止跨模板/跨租户挂字段。
- 前端：三级菜单与模板管理入口只控制呈现，不作为安全边界。
- 快照：下单时一并固化分区与列宽，事后修改模板不影响历史单展示。

## 8. 失败处理与边界情况

| 场景 | 处理 |
| --- | --- |
| 删除仍有字段的模块 | 二次确认后连同字段删除；取消则不动 |
| 列数下调导致跨列越界 | 前端收敛并提示；后端仍做最终校验，越界请求 400 |
| 分区重名 / 空名 | 前端即时提示；后端 400 |
| 模板被停用 | 新建派单下拉不再出现；历史单仍可查看 |
| 老快照无分区信息 | 渲染器回落"单分区单列"，不写库 |
| 保存冲突（他人已改） | 覆盖式更新（本次不引入乐观锁），提示"已保存，请刷新核对" |
| 接口失败 | 保留本地编辑态，不清空表单，不显示假成功 |

## 13. 追加决策（2026-09-12 第二轮反馈）

背景：门店与游戏差异很大——标签命名各自不同，有的门店没有段位加价，有的没有岗位席位。
原设计把「字段 / 岗位 / 段位加价 / 复制文案」四块写死在界面上，过于固定。追加决策：

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D-9 | 表单栅格改为 **2×N** | 每行 2 个字段，行数随字段数量增长；多行文本与说明文字独占整行；窄屏降为单列。布局规则由纯函数 `form-layout.ts` 统一提供，设计器画布与下单表单共用 |
| D-10 | 区块可选、可移除 | 岗位席位、段位加价、复制文案都是**可选区块**：未配置时不显示，不阻塞保存；区块标题的改名需要布局存储（见 D-11） |
| D-11 | 字段标签全部可改名 | 已实现（字段名、占位提示、下拉选项、必填）。区块标题改名、模块分区名属于布局存储，随 `game_dispatch_template_sections` 一起落地 |
| D-12 | 岗位席位可缺省 | 派单领域要求"至少一个位置行"（否则陪玩无法报名）。模板未配置岗位时，下单自动生成一行「陪玩 ×1」，而不是强迫门店先配置岗位名称 |

已实现（无需数据库变更）：

- 2×N 布局 + 宽字段整行 + 窄屏单列，含 9 条单元测试。
- 三个区块可在设计器里一键移除；为空时显示"未启用"说明，不阻塞保存。
- 下单表单在无岗位模板下显示兜底说明，并生成默认位置行。

仍待布局存储（迁移 `20260912090000_dispatch_template_sections`）：

- 每模板可选列数（1–4）、字段"占整行 / 另起一行"的自由开关。
- 模块分区（自定义模块名、分区列数、排序）。
- 区块标题的改名（岗位席位 → 门店自定义叫法）。
