# 派单模板「发布设置与版本历史」设计规格 v0.1

- 状态：**待用户确认观感**（原型已出：`template-publish-prototype.html` / `publish-prototype.png`）
- 日期：2026-09-18
- 范围：`apps/admin-web/app/_lib/merchant-console/template-manager-view.tsx` 的 release Tab（视图层）
- 非目标：不改后端服务、不改 OpenAPI 契约、不改版本/发布/归档机制、**不涉及任何价格**（算价属报名/结算模块，见 `work/session-state-2026-09-18.md`）

## 1. 背景

这一屏是派单模板页三个 Tab 里唯一还没重做的。它现在把六件事平铺在一起：版本历史列表、溯源版本、归档/取消归档/设为默认/删除/复制到游戏、一段"恢复是把历史版本写回草稿"的说明、空状态文案，以及**文案预览**。

问题：动作与状态不分层，危险操作与常用操作并列，用户看不出"我该先干什么"。

## 2. 决策

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| P-1 | 状态与动作分层 | 顺序固定为：当前状态 → 发布（含校验）→ 版本历史 → 折叠的更多操作 |
| P-2 | 校验前置 | 把 `collectDraftIssues` 的结果直接摆在发布按钮旁：提示项用琥珀色，阻断项用红色并**禁用发布按钮**，不再让用户填完备注才吃一次失败 |
| P-3 | 恢复语义不变、提示上移 | **恢复 = 把旧版本写回草稿，线上不变**（用户 2026-09-18 确认）。把它从列表下方的说明文字提到「版本历史」标题右侧，一句话讲清 |
| P-4 | 版本行补「谁发的」 | 每行显示 `vN · 备注 · 时间 · 操作人`；`不可恢复` 仍保留在 v1 等不可恢复行上 |
| P-5 | 危险操作收入折叠区 | 归档 / 取消归档 / 设为默认 / 复制到游戏 / 删除 收进默认折叠的「更多操作」；删除用危险色 |
| P-6 | 文案预览移出本屏 | 该内容已由「渲染」弹层的「订单文案」承载，两处重复。移除本屏的文案预览，**不新增**替代物 |
| P-7 | 溯源版本保留 | 「（可选）溯源版本」留在发布区内，沿用现有交互 |
| P-8 | 视觉沿用已定语言 | 只用商家端 `--mc-*` token 与 `.mc-*` 层；字号 20/15/14/12；圆角与按钮高度与内容设计一致 |

## 3. 现状 → 目标

| 现在 | 目标 |
| --- | --- |
| 版本列表、溯源、危险操作、说明、文案预览混排 | 四段式：状态 / 发布 / 历史 / 更多操作（折叠） |
| 校验结果只有发布失败后才看到 | 校验结果常驻在发布按钮旁，阻断项禁用按钮 |
| 「恢复」的含义写在列表下面 | 提到「版本历史」标题右侧 |
| 版本行没有操作人 | 版本行显示操作人 |
| 危险操作与常用操作同级 | 收进折叠区 |
| 本屏有文案预览 | 移除（渲染弹层的「订单文案」承接） |

## 4. 失败处理

| 场景 | 处理 |
| --- | --- |
| 有阻断项 | 发布按钮禁用，按钮旁说明原因；点击禁用按钮不产生请求 |
| 发布接口失败 | 保留已填备注，显示受控错误（沿用现有 notice） |
| 已归档模板 | 保存/发布继续保持不可用（沿用现状） |
| 版本列表为空 | 显示现有空状态文案 |

## 5. 测试与验收

- 现有 S3 E2E 三条继续全绿；其中归档/取消归档、发布 v1、版本行断言不得弱化。
- 新增断言：发布前有阻断项时按钮为禁用；版本行含操作人。
- 像素级视觉回归基线更新（`tests/e2e/merchant-console-admin.spec.ts-snapshots/` 中与 release Tab 相关的截图，若新增则一并生成）。
- 门禁：`@pw/admin-web` typecheck / build、merchant-console 单测、eslint、prettier。

## 6. 回滚

纯视图层改动，回滚 = 恢复 `template-manager-view.tsx`；无迁移、无契约变化、无持久副作用。
