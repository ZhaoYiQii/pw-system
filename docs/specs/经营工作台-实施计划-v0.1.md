# 经营工作台 v1 实施计划

Goal: 把商家端默认落地页改为“经营工作台”，由一个角色裁剪的只读聚合接口驱动；v1 只展示现有数据可证实的待办、场次、结算与风险，不展示门店应收/实收。
Architecture: 后端新增 `reporting` 只读模块提供 `GET /api/v1/tenant/dashboard/summary`；前端重写 `/merchant-console/work` 的 WorkView 消费该接口；所有待办深链到既有记录/监控页。
Tech stack: NestJS 12 + Prisma + PostgreSQL RLS；Next.js 16 + Tailwind v4（商家端 `mc-*` 设计令牌）+ TanStack Query。
Spec: `docs/specs/经营工作台-设计规格-v0.1.md`
Scope: `apps/api/src/modules/reporting/**`、`apps/api/src/app.module.ts`、`apps/admin-web/app/(tenant)/merchant-console/work/**`、`apps/admin-web/app/_lib/merchant-console/{work-view,merchant-api,modules,workbench-data}.ts*`、`tests/integration/dashboard-summary.spec.ts`。
Non-goals: 不新增门店收入分录/迁移；不接真实支付；不改订单/场次/结算状态机；不做视觉风格重做；不做客户流失预警。
Permission gates: 无安装、迁移、云服务、提交、推送或部署动作。集成测试需要本地 Docker PostgreSQL（现有 `postgres:18` 端口 5433）。
Completion evidence: 后端集成测试通过；openapi:check 通过；前后端 typecheck/build 通过；owner/cs 双角色手工冒烟截图。

## 项目约束（直接来自规格，实施不得放宽）

1. 金额一律 `bigint` 分存储，接口输出十进制字符串分，禁止 number。
2. 租户只允许来自 `TenantContext.tenantId`；前端传参不得决定租户。
3. 后端按角色裁剪财务字段；前端隐藏不等于授权。
4. v1 不产生“门店应收/实收/毛利”数字；UI 只显示“经营入账待开通”占位或省略。
5. `CUSTOMER_SERVICE` 不接收 `pendingSettlementCount/pendingSettlementAmountFen` 及 `SETTLEMENT_TODO` 风险项；可继续查看经手订单金额。
6. 接口只读：不写库、不触发状态迁移。

### 1.4 口径（本 Task 内锁定，全部以现有表与状态为准）

- “今日”：Asia/Shanghai 自然日；由 `now()` 计算 `[dayStart, dayEnd)`，统一比较 UTC。
- `todoOrders`：`orders.status IN ('DRAFT','CONFIRMED','DISPATCHING','PENDING_CONFIRMATION')` 计数（覆盖 CLASSIC 与 GAME_DISPATCH 两种流程，因二者都写入同一 `orders` 主状态）。
- `liveSessions`：`service_sessions.status='STARTED'` 行数 + `slot_sessions.status='STARTED'` 行数（如代码中存在 `IN_PROGRESS` 历史值，查询同时包含）。
- `todayServiceCount`：结束时间落在今日的已结束场次（`service_sessions.ended_at` 且状态为 `ENDED/CONFIRMED_SESSION`；`slot_sessions.ended_at` 且状态为 `ENDED`）所关联的去重 `order_id` 数。
- `financeTodos`：`settlement_batches.status IN ('DRAFT','REVIEWED','APPROVED')` 行数。
- `pendingSettlementCount/Amount`：同一状态集合下 `COUNT(*)` 与 `SUM(total_amount_fen)`。
- `openDisputes`：`disputes.status='OPEN'` 计数。
- `riskAlerts`：`financeTodos + openDisputes + session_adjustments.status='PENDING' 计数`（CS 角色去除 financeTodos 后计算）。
- `attention`：最多 8 条，顺序为“待办订单（最多 5）→ 需复核调整/待确认场次（最多 3）→ 非 PAID 结算批次（最多 2）→ OPEN 争议（最多 2）”，按 `occurredAt` 倒序合并后截断 8。
- `riskFeed`：`attention` 中结算与争议之外另取调整待复核，最多 5 条；`SETTLEMENT_TODO` 条目含 `amountFen`。

### 1.5 角色掩码（domain 纯函数）

```ts
type StaffRole = "TENANT_OWNER" | "TENANT_ADMIN" | "CUSTOMER_SERVICE" | "FINANCE";
function applyRoleMask(role: StaffRole, summary: DashboardSummary): DashboardSummary;
```

- `CUSTOMER_SERVICE`：删除 `financeTodos`、`pendingSettlementCount`、`pendingSettlementAmountFen`；从 `riskFeed` 删除 `kind === "SETTLEMENT_TODO"`；`riskAlerts` 相应重算。
- 其余角色：原样返回。

### 1.6 先写失败测试，再实现

`tests/integration/dashboard-summary.spec.ts` 必须覆盖：

1. 空门店：各计数为 0、`attention=[]`、`riskFeed=[]`，HTTP 200。
2. owner/admin/finance 均可见 `pendingSettlementAmountFen` 与 `financeTodos`；CS 响应缺省这些字段且 riskFeed 无 `SETTLEMENT_TODO`。
3. 预置一笔 `DRAFT` 批次 + 一笔 `PAID` 批次：仅 `DRAFT` 计入且金额正确。
4. 预置今天结束的场次与两天前结束的场次：`todayServiceCount` 只计今天。
5. 跨租户：B 店 token 请求 A 店路径按仓库既有隔离语义返回 404/403。
6. `PLAYER`/`CUSTOMER` 角色返回 403。
7. `attention` 中至少出现订单、结算、争议三类样本且排序倒序。

## Task 2（Slice B）：商家端经营工作台

### 2.1 Objective

重写 `/merchant-console/work`，用 Task 1 接口渲染经营工作台；角色相关区块按权限显示；金额位只展示“结算待办（陪玩应付）”与“经营入账待开通”占位。

### 2.2 Files

Modify:

- `apps/admin-web/app/_lib/merchant-console/merchant-api.ts`：新增 `DashboardSummary`、`AttentionItem`、`RiskFeedItem`、`DashboardMetrics` 类型。
- `apps/admin-web/app/_lib/merchant-console/modules.ts`：`work` 模块 `label` 改为“经营工作台”，同步 `description`。
- `apps/admin-web/app/_lib/merchant-console/work-view.tsx`：整体替换为工作台页面。

Create:

- `apps/admin-web/app/_lib/merchant-console/workbench-data.ts`：纯函数（角色可见性、待办到深链映射、占位文案）。
- `apps/admin-web/app/_lib/merchant-console/workbench-data.spec.ts`：上述纯函数测试。

### 2.3 页面结构（沿用 `mc-*` 商家端设计令牌）

自上而下：

1. 页头：门店名、日期、今日已服务/进行中场次；右侧 `AI 录单`（`/merchant-console/ai`）、`新建派单`（`/merchant-console/dispatch/new`）。
2. 财务可见区（OWNER/ADMIN/FINANCE）：卡片“结算待办 ¥X · n 笔”（深链 `/merchant-console/settlements`）+ 卡片“经营入账（应收/实收/毛利）待开通”（禁用态，不深链）。CS 不渲染该区。
3. 指标带：待办订单、进行中场次、财务待办（CS 不显示）、争议/异常；点击各自深链。
4. 需要处理：渲染 `attention`，无数据时显示空态。
5. 风险与提醒：渲染 `riskFeed`。
6. 快捷动作：AI 录单、登记收款（`/merchant-console/finance`）、生成结算批次（`/merchant-console/settlements`）。

### 2.4 深链映射（`workbench-data.ts` 纯函数）

| kind | refType | 目标路径 |
| --- | --- | --- |
| `ORDER_TODO` | `DISPATCH` | `/merchant-console/dispatch/{refId}?kind={flow==='GAME_DISPATCH'?'GD':'CLASSIC'}` |
| `SESSION_TODO` | `SESSION` | `/merchant-console/sessions/{refId}` |
| `SETTLEMENT_TODO` | `SETTLEMENT_BATCH` | `/merchant-console/settlements/{refId}` |
| `DISPUTE_TODO` | `DISPUTE` | `/merchant-console/disputes/{refId}` |

`SETTLEMENT_BATCH`/`DISPUTE` 详情路由在提交前先以冒烟确认 `/merchant-console/[module]/[recordId]` 可打开；若不存在详情页则回退到模块列表 `/merchant-console/settlements`、`/merchant-console/disputes`（验收记录中注明最终映射）。

### 2.5 行为要求

- `useQuery` key：`["merchant","dashboard-summary"]`；`staleTime: 15_000`；该查询单独开启 `refetchOnWindowFocus`。
- loading / error / empty / offline / 403 状态齐全；接口失败不渲染旧数据冒充实时。
- 金额用 `formatFenYuan`（现有 `money.ts`）与等宽样式；`pendingSettlementAmountFen` 缺失时不显示“¥0”。
- CS 缺省财务字段时不渲染财务卡，也不显示“无权限”错误。

### 2.6 前端纯函数测试

`workbench-data.spec.ts` 覆盖：

1. `canSeeFinance(role)`：owner/admin/finance true，cs false。
2. `attentionHref(item)`：四类 kind 返回预期路径（含 flow 分支）。
3. `financePlaceholder(role, metrics)`：有财务权限且无收入字段时显示“经营入账待开通”；无权限返回 null。
