# ADR-0003：算价模型（陪玩×游戏底价 + 按游戏规则库 + 报单时长）

- 状态：**建议，待用户批准**（2026-09-20）
- 背景：
  - 订单定价目前在代码里有**两条并行路径**：经典派单选人用模板快照的 `rankRulesJson`（段位加价），通用模板下单用模板字段选项的 `addPriceFen`（SUM/MAX）。同一笔订单的钱可能由两套规则各算一半。
  - 陪玩底价 `PlayerProfile.basePricePerHourFen` 是**陪玩级**的，无法表达"同一个陪玩在不同游戏定价不同"。
  - 计费时长来自系统证据计时（`SlotSession.startedAt/endedAt`），与产品要求的"陪玩结束服务时报单填写总时长 + 上传截图证据"不一致。
- 约束：
  - 金额一律整数分（bigint），禁止浮点（主规格 10.5 / ADR-008）。
  - 租户隔离：所有定价与规则必须带 `TenantContext`，禁止信任客户端 `tenantId`。
  - ADR-0002 已冻结 CLASSIC 旧流程，本决策只作用于 game-dispatch 主线。
  - 历史订单不受影响：规则与单价必须以快照形式落在订单侧，事后改规则不得回写历史金额。
- 候选方案：
  1. **新增陪玩×游戏底价表 + 独立的按游戏定价规则库**，模板不再持有价格（**本 ADR 选择**）。
  2. 保留模板快照 `rankRulesJson`，只扩展支持固定价——改动最小，但双轨继续存在，且改规则要重发模板才生效。
  3. 继续把价格放进模板字段选项——价格与表单结构耦合，无法表达"整游戏定价"。
- 决策：
  1. 新增 `player_game_prices`（陪玩 × 游戏底价）；`PlayerProfile.basePricePerHourFen` 降级为兜底默认。
  2. 新增 `game_pricing_rules`（按游戏绑定，`SURCHARGE` 加价 / `FIXED` 固定价两类），作为定价的**唯一权威**。
  3. 计价：`单价 = 固定价 ?? (底价 + Σ命中加价)`；`订单金额 = Σ(单价 × 申报时长 / 60)`（向上取整到分）。
  4. 时长以**陪玩报单申报**为计费依据，截图证据用于人工核查；商家确认环节可修正并留审计。
  5. 平台抽成置 0：`订单金额 = 陪玩实收 + 门店抽成`，`门店毛利 = 订单金额 − 陪玩实收`。
  6. 模板快照与字段选项中的旧价格字段进入 legacy 只读兼容期，不再作为定价来源。
- 理由：目标本身就是"按游戏隔离定价"，而模板/字段选项不是游戏维度的载体；两套加价路径并存会让金额口径无法审计；平台费置 0 不需要改公式，回退成本低。
- 影响：订单侧单价/金额继续以快照落库（历史不可变）；商家需要在规则库页维护各游戏规则；陪玩端新增报单表与报名/取消按钮；OpenAPI 契约需重生成。
- 迁移方式：幂等脚本把现有 `rankRulesJson` 与字段选项 `addPriceFen` 归并为该游戏的规则项（同游戏同段位取最新快照值），迁移报告列出冲突项；旧字段保留只读一个版本。
- 回滚方式：新表可停用并回退到旧字段读取；旧字段未删除；已产生的订单快照不重算。
- 验证：定价纯函数单测（固定价优先 / 加价 / 兜底 / 无价拒绝 / 取整）、报名→选中→报单→核算集成用例、无人报名自动关单与并发关单用例、契约断言、三端构建与全套门禁。
- 批准记录：待用户批准。
