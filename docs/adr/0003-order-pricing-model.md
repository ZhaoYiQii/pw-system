# ADR-0003：算价模型（陪玩×游戏底价 + 按游戏加价规则库 + 报单时长）

- 状态：**已批准（用户 2026-09-20）**
- 背景：
  - 订单定价目前在代码里有**两条并行路径**：经典派单选人用模板快照的 `rankRulesJson`（段位加价），通用模板下单用模板字段选项的 `addPriceFen`（SUM/MAX）。同一笔订单的钱可能由两套规则各算一半。
  - 陪玩底价 `PlayerProfile.basePricePerHourFen` 是**陪玩级**的，无法表达"同一个陪玩在不同游戏定价不同"。
  - 计费时长来自系统证据计时（`SlotSession.startedAt/endedAt`），与产品要求的"陪玩结束服务时报单填写总时长 + 上传截图证据"不一致。
  - 报名界面的展示物与产品原意不符：需要展示的是**单价**（底价 + 加价），不是含时长的总价。
- 约束：
  - 金额一律整数分（bigint），禁止浮点（主规格 10.5 / ADR-008）。
  - 租户隔离：所有定价与规则必须带 `TenantContext`，禁止信任客户端 `tenantId`。
  - ADR-0002 已冻结 CLASSIC 旧流程，本决策只作用于 game-dispatch 主线。
  - 历史订单不受影响：规则与单价必须以快照形式落在订单侧，事后改规则不得回写历史金额。
- 候选方案：
  1. **新增陪玩×游戏底价表 + 独立的按游戏加价规则库**，模板不再持有价格（**本 ADR 选择**）。
  2. 保留模板快照 `rankRulesJson`，只做字段扩展——改动最小，但双轨继续存在，且改规则要重发模板才生效。
  3. 继续把价格放进模板字段选项——价格与表单结构耦合，无法表达"整游戏定价"。
- 决策：
  1. 新增 `player_game_prices`（陪玩 × 游戏底价）；`PlayerProfile.basePricePerHourFen` 降级为兜底默认。
  2. 新增 `game_pricing_rules`（按游戏绑定），作为定价的**唯一权威**；规则项以 **`dimensionKey`（模板字段 stableKey + 选项值）** 为命中键，段位不是专用维度；本版只实现 `SURCHARGE`（加价），`FIXED`（固定价）保留类型位但不在本版实现——固定价由客服在派单时填写，后续单独立项。理由：干跑实测现行 62 条加价全部挂在 `mode` 字段上，写死段位会丢失全部现行加价。
  3. 计价：`单价 = 底价(陪玩×游戏，缺省兜底) + Σ命中维度键的加价`；`订单金额 = Σ(单价 × 申报时长 / 60)`（向上取整到分）；订单默认时长 60 分钟，仅用于结算前的估算与钱包余额校验。
  4. 迁移只处理已归类到游戏的模板；`game_id` 为空的未归类模板跳过并写入报告，不引入"未归类兜底规则"（保持规则按游戏隔离）。
  4. 时长以**陪玩报单申报**为计费依据，开始/结束截图证据复现有 `SlotEvidence` 通道，供**客服审批**时人工核查；审批环节可修正时长并留审计。本版**不做**申报时长与证据计时的自动比对/标记（智能核验列为后续项，不引入相关字段）。
  5. 平台抽成置 0：`订单金额 = 陪玩实收 + 门店抽成`，`门店毛利 = 订单金额 − 陪玩实收`。
  6. 报名界面展示**单价**（老板与陪玩同一数字，不乘时长）；陪玩实收在报单后才展示。
  7. 选中（锁定）后陪玩不可自助取消，需商家释放名额；人工认定放鸽子时记录违约并通知老板。
  8. 本版不实现时长智能核验（申报 vs 证据自动比对标记）；只保存截图与申报值，由客服在审批时人工判断。
  8. 模板快照与字段选项中的旧价格字段进入 legacy 只读兼容期，不再作为定价来源。
- 理由：目标本身就是"按游戏隔离定价"，而模板/字段选项不是游戏维度的载体；两套加价路径并存会让金额口径无法审计；把固定价拆出去可以让本版聚焦"底价+加价+报单"这条主链；平台费置 0 不改公式，回退成本低。
- 影响：订单侧单价/金额继续以快照落库（历史不可变）；商家需要维护各游戏的加价规则；陪玩端新增报单表与报名/取消按钮，并新增违约记录与通知；OpenAPI 契约需重生成。
- 迁移方式：幂等脚本把 v1 `game_dispatch_rank_rules`（`rankLabel → addPriceFen`）与 v2 模板配置选项的 `priceDeltaFen` 归并为该游戏的 `SURCHARGE` 规则项（维度键分别为 `rank=<label>` 与 `<stableKey>=<optionValue>`），按 `templateId → game_id` 归并；未归类模板跳过并报告；冲突项只报告不自动裁决；旧字段保留只读一个版本。`scripts/migrate-pricing-rules.mjs` 的只读干跑已产出该报告。
- 回滚方式：新表可停用并回退到旧字段读取；旧字段未删除；已产生的订单快照不重算。
- 验证：定价纯函数单测（加价命中 / 兜底 / 无价拒绝 / 按游戏隔离 / 取整）、报名→选中→报单→核算集成用例、无人报名自动关单与并发关单用例、选中后自助取消被拒（409）、契约断言、三端构建与全套门禁。
- 批准记录：产品口径与架构决策均由用户于 2026-09-20 批准（含"时长智能核验本版不做"的裁定）。
