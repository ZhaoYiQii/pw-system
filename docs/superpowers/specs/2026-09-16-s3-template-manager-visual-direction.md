## 1. 主体与页面唯一的任务

**主体**：陪玩门店的店长/运营（桌面端），他们自己就是玩家——习惯阵容席位、段位阶梯、开黑房号、战绩面板这类"把人和条件摆在一张板上"的表达。

**页面唯一的任务**：把「这一单要问客户什么、要几个人、加价多少」编成一份**可以发布、可以回滚**的派单表单。

**真实失败模式只有两个**：

1. 店主以为「关闭开关」= 删除、以为空位不存在，于是重复添加、结构越改越乱；
2. 店主删除了正被"人数来源/加价规则"引用的组件，保存或发布时才被打回。

视觉方向必须让这两件事**在看之前就看得见**。这是本方向全部取舍的判据。

## 3. 本次新增的工作区 token（3 个 + 1 个可测派生）

只在模板工作区作用域内定义，不污染控制台其它页面：

| Token             | 值                    | 用途           | 理由                                                                                                                     |
| ----------------- | --------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `--tm-board`      | `#eef3f4`             | 编辑底板底色   | 比控制台底再冷一档，让"底板"是明确的工作面而不是又一块面板                                                               |
| `--tm-grid`       | `rgba(21,32,43,0.06)` | 底板单位网格线 | 列宽是真实数据，用几何表达而不是再写一个标签                                                                             |
| `--tm-slot`       | `#ffffff`             | 席位底         | 与控制台纸面同色，靠尺寸与网格对齐区分"可移动的件"与"面板"                                                               |
| `--tm-amber-text` | `#7d581a`             | 状态文字级琥珀 | 实测 `--mc-amber`(#a66e13) 在白底仅 **4.32:1**（未达 AA）；本值 = 72% amber + 28% ink → 白底 **6.40:1**、琥珀浅底 5.90:1 |

> 附带发现（本次未修，属跨页问题）：`--mc-amber` 直接被当作**文字**色时在白底同样只有 4.32:1；控制台其它页面若用它渲染状态文字存在同一问题，建议后续单独开一个小任务统一替换为派生值。

> 第二个 token 事实：`--mc-green` 与 `--mc-accent` 在已实现 token 中是**同一个值** `#189c91`，因此"成功/生效"与"主操作"无法用色相区分。本方向的处理是：状态点、生效版本、开关一律用**墨色 + 文字标签**表达，teal 严格只留给动作按钮。若产品要求真正的成功绿，需要新增一个色相（属新的颜色决策，需单独确认）。

> 3. **主操作 teal 已调（2026-09-16）**：原 `#189c91` 配白字只有 **3.39:1**（AA 要求 4.5:1），作为文字放在 `--mc-accent-2` 浅底上仅 **3.00:1**。改为 **`#11786f`**：白字 5.33:1、`--mc-paper` 5.33:1、`--mc-paper-2` 5.05:1、`--mc-accent-2` 4.72:1、`--mc-bg` 4.91:1 —— 四种底色全部达 AA，且色相最接近原值。备选 `#106f68`（6.01:1）更稳但明显偏深；`#0f7f76` 在 `--mc-accent-2` 上只有 4.31:1，未达 AA，已排除。

语义分工（关键决定）：**teal 只用于动作**（保存/发布/新增），**蓝色专用于绑定与引用（锚点）**，琥珀专用于"需要人工确认"，红色专用于阻断。一个颜色只讲一件事。

## 4. 字体与字号

不引入新字体（控制台统一使用系统中文字体栈 + 等宽数字栈；新增 webfont 会与既有页面割裂，且需要额外依赖授权）。个性来自**等宽数字承担状态表达**：

| 角色         | 规格                               | 出现位置                     |
| ------------ | ---------------------------------- | ---------------------------- |
| 眉标 eyebrow | 10px mono，`letter-spacing: .13em` | 席位分数、绑定类型、版本前缀 |
| 席位名       | 13px / 500 系统中文字体            | 组件卡片标题                 |
| 席位说明     | 11px `--mc-muted`                  | 帮助文本、绑定说明           |
| 区块标题     | 15px / 600                         | 区块带标题                   |
| 版本与修订   | 12px mono + `tabular-nums`         | `v3 · r8`、版本带、`1000分`  |

金额同时给出元换算，但**分是唯一权威值**；人数、列宽分数、版本号一律等宽对齐。

## 5. 布局概念

工作区三栏，全部在控制台壳内（侧栏 232px 不变）：

```
┌ 页头：派单模板 · 英雄联盟 ▾ ｜ 状态 ▾ ｜ 搜索 ｜ [新建模板] ──────────────┐
├ 模板轨道 (Roster Rail) ┬ 编辑底板 (Board) ────────────────┬ 检查器 ──────┤
│ ▸ 排位陪练·标准版      │ ▍下单信息        1/2 1/2 整行      │ 属性         │
│   v3 · r8 · 有未发布   │ ┌───────┬───────┐               │ 绑定与计算    │
│   ● 默认               │ │游戏大区│游戏模式│ ← 席位        │ 校验问题      │
│ ▸ 未归类（旧模板）      │ ├───────┴───────┤               │ 版本历史      │
│ ▸ 五排陪练·轻量版      │ │目标段位  ⚓人数  │               │              │
│                       │ └───────────────┘               │              │
│                       │ ┊ 待填席位 ┊ + 添加内容           │              │
├───────────────────────┴──────────────────────────────────┴──────────────┤
│ 状态条：v3 · r8 · 林店长 · 有未发布改动        [保存草稿] [预览] [发布]     │
└──────────────────────────────────────────────────────────────────────────┘
```

- **模板轨道**：一行一条，状态点 + 版本 + 未发布/默认标记；未归类单独成组置底，不做游戏图标猜测。
- **编辑底板**：区块带（标题 + 列宽分数）+ 席位网格；底板背景按该区块列数画单位网格线。
- **检查器**：随选中席位切换的窄栏（属性 / 绑定与计算 / 校验问题 / 版本历史），不抢主视线。
- **状态条常驻页脚**：线上版本、草稿 revision、最后编辑人、未发布标记与三个主要动作永远在同一处。

三个标签切换的是**检查器内容域**，底板始终可见：内容设计、业务绑定与计算、发布设置与版本历史。这样"改结构"和"看影响"不会互相打断。

## 6. 签名元素：席位底板 + 锚点

整个界面唯一被记住的东西，也是唯一敢花力气的地方：

1. **席位**：每个组件是按真实列宽绘制的白色件（`1/2`、`整行`），宽度对齐底板单位网格，分数徽标用等宽字。列宽不只是设置项里的数字。
2. **空位**：未被占用的网格单位画成 `┊ 待填席位 ┊`（虚线），每行末端一个 `+ 添加内容`；空位存在但不喧哗。
3. **禁用席位**：保留原件，叠加斜向细线并降饱和，徽标改为 `待用`——禁用≠删除在视觉上不可混淆。
4. **锚点**：被"人数来源"或"加价规则"引用的席位，左边 2px 蓝边 + `⚓ 人数来源` / `⚓ 加价 ×4` 等宽标签；删除/禁用前先看到锁。绑定关系在检查器内表达，不画穿屏箭头。

**风险与理由**：这比常规后台"列表 + 属性面板"更接近仪表盘，密度更高，是一处刻意的美学冒险。敢这么做，是因为本页两个最贵的错误都由"看不见结构"造成；底板把列宽、空位、禁用、引用四件事变成几何事实，而不是靠读标签推断。风险由纪律约束：只用一个强调色、网格线 6% 透明度、动效 ≤160ms、无渐变无玻璃拟态。

## 7. 发布标签的视觉：版本带

发布不是第三个灰色表单，而是一条**版本带**：

```
版本带： [v1] [v2] [v3 ●正在生效]  ┊ 草稿 r8（有未发布改动）┊  [发布]
还原：   [v2 恢复到此] → 草稿 r9（不改线上；发布前 v3 不动）
```

- 生效版本实心、历史版本描边、草稿用虚线位表达"还没有版本号"。
- 发布 = 草稿从虚线位进入版本带（≤160ms）；保存草稿**不动**版本带，只更新 `r` 与未发布标记。
- 冲突（409）在状态条上方出现常驻提示条，保留本地内容，提供「重新加载服务端」与「复制我的内容」两个明确动作。

## 8. 动效（只有三处，其余为静）

| 位置          | 行为                        | 时长                                   |
| ------------- | --------------------------- | -------------------------------------- |
| 席位移动/排序 | 让位过渡（含键盘上移/下移） | 140ms                                  |
| 发布          | 草稿位 → 版本带             | 160ms                                  |
| 校验错误定位  | 锚点脉冲一次                | 300ms，`prefers-reduced-motion` 下取消 |

除加载态外无氛围动效、无滚动视差。

## 10. 明确不做（自检结论）

- 不用**暖米色 + 衬线大标题 + 陶土橙**：那是平台端（`.pw-platform`）的身份，商家端用它会串台。
- 不用**近黑底 + 荧光强调色**：本页是长时间密集编辑的浅色工作台，暗底会与控制台壳打架。
- 不用**报纸式零圆角 + 满屏细线**：细线只用在底板网格这一处（它编码列宽），席位仍需圆角表达"可移动的件"。
- 不加编号标记（内容不是序列）、不加渐变/玻璃/装饰插画、不加"大数字英雄区"、不加鼠标跟随或粒子。

## 11. 质量地板（不声明的部分）

- 键盘：席位可用键盘上移/下移且顺序与拖拽一致；焦点可见（沿用控制台 focus ring）；对话框关闭后焦点回到触发元素。
- 错误：校验问题定位到区块与席位，并用 `aria-live="polite"` 宣告。
- 响应式：底板 <768px 降为单列；检查器变下方抽屉；状态条动作保持可达。
- 对比度：正文与席位文字对 `#ffffff` 达 AA；teal 只用于按钮底或 ≥16px 强调文字，不用于小字正文。
- 窄屏不出现横向溢出。

## 12. 与实现栈的映射

- 按钮、徽章、输入、表格沿用 `apps/admin-web/components/ui/*`（badge/button/card/input/table）。
- 复用商家端既有的 `.mc-designer*` 词汇（检查器、属性行、空态、添加位已在 `merchant-console.css` 中存在），只在其上补充底板/席位/锚点/版本带所需的 `mc-tm-*` 类，**不再新增第三套并行命名**；不新增全局 token、不改平台端与其它商家端页面。
- 布局计算复用 `form-layout.ts` 的 2×N 规则；视觉不改变布局规则，只表达它。
